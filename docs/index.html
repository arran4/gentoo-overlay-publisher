Gentoo Overlay Publisher

A Go library and GitHub Action that generate Gentoo ebuilds for binaries already released by GoReleaser, then propose overlay updates through pull requests.

Project status: Design and foundation. The library, executable and Action are not yet released. This documentation is an intentionally lightweight starting point.

Boundary: The publisher does not compile or upload upstream binaries, and does not create application releases. It publishes ebuilds and required overlay metadata only.

Three interfaces, one engine

Go library

Construct ebuilds with a typed IR, update metadata and Manifests, and produce inspectable change plans. No G2 or build-tool imports in the core.

GitHub Action

Primary workflow integration: discover assets, calculate fresh changes automatically and open a reviewable overlay pull request.

CLI

Scriptable and local use of the same engine. Default publish, optional read-only plan, and local-only apply.

Intended source inputs

The first integration targets already published GoReleaser-produced binary archives, using GitHub Release assets and, when available, GoReleaser artifact metadata. Other release systems remain deferred, and routine users should not need a custom YAML manifest.

Safety and verification

Publishing must reconcile a freshly read target state and produce an overlay-only branch and pull request rather than committing directly to the default branch. Verification may independently use G2 and Portage; secret-bearing publication tests must run only from trusted workflows.

Configuration and workflows

The workflow author chooses when to invoke the Action: after a published GitHub Release, after their existing GoReleaser upload step, or through another trusted workflow trigger. A separate custom candidate manifest is not normally required. The publisher may read a restricted set of archive/build hints from the matching GoReleaser configuration, combine them with explicitly configured Gentoo policy and apply safe defaults.
